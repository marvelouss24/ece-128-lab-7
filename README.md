# ece-128-lab-7
ECE 128 Lab 7. Design and Implementation of an up counter using a Moore state machine in Verilog using Vivado

### Project Description
We were tasked with designing an up counter in Verilog that displays its count on the seven-segment display of a physical FPGA board. To accomplish this, we broke the design into modular pieces: a clock driver that divides the board’s fast clock down to slower clocks, a counter that increments at a human-visible rate, a binary to BCD converter that turns the count into decimal digits, and a BCD to seven-segment decoder that determines which segments light up for each digit. Because the board has multiple digits that share the same segment lines, we also built a multi-segment driver that rapidly cycles through the digits so they all appear lit at once. We then connected these modules in a top module. To verify the design, we wrote a testbench for the top module, and we temporarily sped up the internal clocks in simulation so the counting could be observed without an extremely long waveform. Finally, we implemented the design on an FPGA by running synthesis and implementation in Vivado, generating the bitstream, and programming the board using a constraint file that maps the inputs and outputs to the board’s switches, buttons, and displays.

### Instructions
There are 6 design files. One for a binary to BCD converter, one for a clock driver, one for a counter, one for a multi segment driver, one for a BCD to seven segment display converter, and a top module to actually create the top module. In order to simulate the top module, there are two options. The first one is to use the original clock values intended for the FPGA, all this requires is using the top module test bench and running the simulation. However in order to see the counting up, since the clock for counting is a value the human eye can see, it results in a very long waveform being needed to see the counting up. The other option is to edit the 
top module by changing the instantiations for the counter and multi segment driver. For the counter, change the clock from q[26] to q[5] and for the multi segment driver, change the clock from q[16] to q[1]. However doing it this was will result in the implementation not being correct on the FPGA so you must change it back to the original values after the simulation is ran. To implement the design on the FPGA, you must set the file top.v as the top design source. After that, run the synthesis, implementation, and then generate the bitstream. Finally, program the board using the hardware manager and then follow the constraint file, up_counter_constraints.xdc to see how the inputs and outputs are mapped to the FPGA.
